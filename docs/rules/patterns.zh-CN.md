# 常用模式

## 骨架项目

实现新功能时：
1. 搜索经过实战检验的骨架项目
2. 使用并行智能体评估选项：
   - 安全评估
   - 可扩展性分析
   - 相关性评分
   - 实现规划
3. 克隆最佳匹配作为基础
4. 在经过验证的结构中迭代

## 设计模式

### Repository 模式

将数据访问封装在一致的接口之后：
- 定义标准操作：findAll、findById、create、update、delete
- 具体实现处理存储细节（数据库、API、文件等）
- 业务逻辑依赖抽象接口，而非存储机制
- 便于切换数据源，并简化使用 mock 进行测试

### API 响应格式

为所有 API 响应使用一致的信封格式：
- 包含成功/状态指示符
- 包含数据载荷（错误时可为空）
- 包含错误消息字段（成功时可为空）
- 为分页响应包含元数据（total、page、limit）
